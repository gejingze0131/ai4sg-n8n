Literature search and structured evidence extraction on **AI for Social Good (AI4SG) tools in the education sector**.

## **1. Objective**

Identify relevant empirical studies, evaluations, working papers, government reports, and credible institutional reports on **AI-enabled education tools that have been actually tested, deployed, implemented, or used in real educational settings**.

The purpose is **not** to assess whether the literature is strong or weak, identify research gaps, or rank papers by causal quality.

The purpose is to extract factual information that can later be used for analysis of:

- intervention

- adoption

- effectiveness

- implementation

- deployment

- scaling

- cost

- financing

Focus on collecting accurate and comparable information across studies.

## **2. Definition of AI4SG in education**

For this review, define **AI4SG in education** as:

> The use of AI-enabled systems to address socially important educational problems by improving learning, access, equity, inclusion, teaching capacity, or the efficiency and quality of education delivery, especially where students, teachers, schools, or education systems face resource, capacity, or access constraints.

Do not require the paper itself to use the term "AI for Social Good."

Include an application when:

1.  AI is a substantive component of the tool or service;

2.  the application addresses an educational problem; and

3.  the intended outcome concerns learning, access, equity, inclusion, teaching capacity, affordability, or education-system performance.

## **3. AI applications to include**

Include, where relevant:

- intelligent tutoring systems

- personalized adaptive learning

- adaptive learning platforms

- generative-AI or LLM tutors

- educational chatbots

- teacher copilots

- AI-assisted teacher support

- automated feedback

- automated assessment

- AI-supported formative assessment

- dropout or learning-risk prediction

- early-warning systems

- AI for accessibility or special education

- AI translation or language-learning systems

- AI-supported education administration

- AI-supported public-service delivery in education

Older systems may be included if adaptive algorithms, learner modelling, prediction, NLP, automated personalization, or automated feedback are substantive components.

Exclude ordinary digital education tools where AI is not a substantive component.

## **4. Type of evidence to prioritize**

Prioritize sources that contain information on **real interventions or real deployments**, including:

- randomized trials

- field experiments

- quasi-experimental evaluations

- implementation studies

- deployment evaluations

- scaling studies

- observational studies using actual usage data

- government evaluations

- international-organization reports

- credible program evaluations

- implementation reports

- cost or financing reports

Do not prioritize:

- opinion pieces

- purely conceptual papers

- general discussions of AI in education

- attitude-only studies

- intention-to-use surveys without actual usage data

- purely technical machine-learning papers without real educational deployment

- papers where AI is used only for generic convenience

## **6. Unit of analysis**

Use the **AI intervention or deployment** as the main unit of analysis, rather than the paper alone.

If several papers evaluate the same AI tool in different settings or stages, treat them as separate intervention records but connect them using a common:

- Tool / program name

- Organization / provider

- Program ID if useful

For example, a pilot study and a later government-scale deployment of the same tool should be recorded separately.

## **7. Information to extract**

For every relevant intervention, extract only information that is directly useful for later analysis.

### **A. Source information**

- Full citation

- Authors

- Year

- Journal or institution

- DOI

- Official URL

- Publication type

### **B. Context**

- Region or city, if reported

- Country income level

- Urban / rural / mixed

- Public / private education setting

- Education level

- Subject area

- Target population

- Age or grade

- Number of students

- Number of teachers

- Number of schools

- Other relevant sample characteristics

### **C. Educational problem**

Record the main problem the AI tool is intended to address.

Examples:

- low learning outcomes

- students below grade level

- teacher shortage

- limited teacher expertise

- high student-teacher ratio

- lack of individualized feedback

- dropout

- low attendance

- limited educational access

- language barriers

- disability-related barriers

- weak assessment capacity

- administrative inefficiency

Use the authors' description where possible.

### **J. Scaling**

Extract factual information on:

- initial pilot size

- later deployment size

- number of students

- number of teachers

- number of schools

- number of districts

- number of regions

- geographic expansion

- expansion over time

- whether government adopted the tool

- infrastructure changes

Do not label something "scaled" only because the authors describe it as scalable. Record actual deployment numbers where possible.

## **8. Missing information**

Do not guess.

If a field is unavailable, record:

**Not reported**

If information was searched for but could not be verified, record:

**Not verified**

Do not infer values from surrounding information.

Use **one row per intervention/deployment**, not necessarily one row per paper.

Keep each cell concise but information-rich.

Where one source provides several relevant quantitative results, include the main results rather than summarizing them only as "positive" or "negative."

## **10. Final output requirements**

The main output should be a **clean, verified evidence database** that can later be used for cross-study analysis.

The goal is:

> **To collect comparable factual information on how AI education tools are designed, adopted, implemented, deployed, used, scaled, funded, and associated with educational outcomes.**
